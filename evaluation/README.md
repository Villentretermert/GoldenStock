# GS-004: протокол качества v0.1

Синтетический стартовый корпус проверяет инструменты оценки. Он не измеряет качество реальной ИИ и не заменяет независимую разметку английских финансовых документов. GS-004 остаётся на приёмке до независимой проверки корпуса.

## Выполнение
```powershell
python evaluation/build_starter.py
python -m unittest discover -s evaluation -p "test_*.py" -v
python evaluation/score.py evaluation/datasets/synthetic-v0.1/dev.json evaluation/datasets/synthetic-v0.1/dev.json
```
Последняя команда — self-check scoring, не AI benchmark. Отдельного inference сейчас нет.

## Accuracy 95%
Единица оценки: факт с company, metric, period, currency, unit, scale, value, source_id, locator. Правильный факт требует совпадения всех полей и численного значения в заданном эталоном допуске. Допуск фиксируется до запуска и не выбирается моделью.

Accuracy = correct / all expected facts. Пропуски и abstentions входят в знаменатель. Precision = correct / all emitted numeric facts; лишние факты снижают precision. Coverage = answered expected / all expected. Схемные ошибки и дубли ID делают run невалидным, а не увеличивают score. Дополнительно нужны разрезы по компании, формату, метрике, OCR/цифровому тексту.

95% на маленькой выборке не доказывает 95% в эксплуатации. Scorer выводит Wilson 95% interval. Приёмка реального корпуса требует accuracy >=95%, отдельно согласованного минимального precision и coverage, размера выборки и отсутствия критических дефектов. Нельзя называть достижением цели простой прогон эталона против себя.

## Корпус и независимость
Старт: 5 вымышленных документов, 20 фактов; split по целому документу: 3 train, 1 dev, 1 holdout. Синтетический holdout публичен разработчику и не является слепым production benchmark. Он служит только для проверки механизма split.
Для пилота: сначала согласовать 5 компаний и права использования документов, затем собрать не менее 30 английских документов и 500 фактов как предварительный план. Доли train/dev/test 60/20/20 по семействам документов; разные версии одного отчёта всегда в одном split. Иначе происходит утечка. Финальные объёмы и стратификация утверждаются после оценки доступного материала.
Первый аналитик размечает факты, второй независимо проверяет значения, период, масштаб и источник. Расхождения рассматриваются третьим решением/владельцем методики. Записываются reviewer_id, timestamp, reason, status. Для закрытого test labels отделены от runtime RAG/промптов; доступ только scorer. До фиксации test запрещена настройка на его ответах.
Каждое изменение корпуса создаёт новую версию и SHA256. Manifest фиксирует source hash, период публикации, split, лицензирование, reviewers. Изменённый эталон нельзя подменять внутри завершённого эксперимента.

## Числа и выводы
Расчётный движок проверяется отдельно: эталонные книги, округления, валюты, инварианты и контрольные суммы. Критические тесты должны проходить полностью; 95% не разрешает ошибки арифметики.
Сводки: аналитик разбивает ответ на утверждения и размечает supported / contradicted / unverifiable. Источник должен подтверждать именно текст утверждения. Доля подтверждённых утверждений, покрытие важных фактов и критические противоречия сообщаются отдельно от extraction accuracy.
Качество прогноза стоимости компании не называется accuracy 95%. Будущая цена не является текущим эталоном финансового расчёта.

## Незавершённая ручная приёмка
Назначить двух разметчиков; подтвердить компании и материалы; независимо проверить стартовый корпус; утвердить реальные split/пороги. Эти действия не выполнены автоматически и не помечены как завершённые.
