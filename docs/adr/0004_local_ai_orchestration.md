# ADR-0004: локальные адаптеры, очередь и RAG
Дата: 2026-10-24. Этап GS-013–016.

## Решение
Используем Ollama внутри закрытой Docker-сети, Python-адаптер и SQL-очередь с единственным активным GPU-вызовом. Профили содержат точный tag и digest весов. Результат хранит версии промпта, хеш схемы и хеш входа. ИИ не получает инструментов, URL назначения, полномочий пользователя или права записи фактов.

Wrapper (адаптер) — `OllamaProvider`: изолирует JSON-протокол провайдера от прикладных задач. Чтобы выбрать другую установленную модель, аналитик выбирает профиль; бизнес-логика остаётся общей. Новый провайдер должен реализовать propose/summarize и те же проверки результата.

Оркестрация — `AIRun`: queued → running → succeeded/failed; отдельные cancel/retry, lease и аудит. Модель не управляет этим графом. GPU-запрос выполняется один, контекст 4096, keep_alive=0 освобождает веса после ответа. Отмена не прерывает вычисление мгновенно: результат отбрасывается, слот занят до возврата или истечения lease. Тайм-ауты и падения дают явную ошибку, автоматического бесконечного повтора нет.

RAG — сначала найти разрешённые свидетельства, затем передать их в генерацию с цитатами. Здесь первая версия использует локальный лексический индекс подтверждённых личных фактов: 512 измерений, SHA-256 хеширование токенов, нормированные частоты и скалярное произведение. Версия `lexical-hash-512-v1`; это не нейросетевой семантический поиск. Индекс строится из ограниченного набора фактов при запросе, не хранит отдельную копию чужих данных. До четырёх фактов входят в сводку; неполнота явно обозначена.

Переносимая память — экспорт JSON knowledge pack: значения, определения, происхождение, версии, последние решения и инструкции. Прежние версии фактов и полная история решений остаются в БД. Пакет можно читать при смене LLM; автоматический импорт в другую установку ещё не реализован.

## Почему пока без LangGraph, CrewAI и MCP/FastMCP
Текущие сценарии линейны и используют фиксированные серверные операции. SQL уже хранит состояние, аудит и повторы; дополнительный агентный runtime дублировал бы этот механизм. MCP пригодится при подключении независимых доверенных сервисов, LangGraph — при ветвящихся процессах с длительными остановками; CrewAI — при измеримой пользе разделённых агентных ролей. Это отложенные варианты, не установленные компоненты. Открытый MCP-вызов из модели сейчас увеличил бы объём проверяемых полномочий без необходимости для сценария.

## Границы
Prompt injection остаётся риском качества: первоначальные модели принимали инструкцию с числом за факт. Явные известные формы инструкции направляются на ручной разбор; это не универсальная защита. Строгая схема ограничивает числа/цитаты/ID, а сервер сверяет происхождение. Пересказ может быть неверен даже с настоящей цитатой: все результаты unreviewed, факты создаёт и подтверждает аналитик.

Публичный коннектор отделён от inference: только фиксированный SEC API, идентифицированный User-Agent, без редиректов, ограничение размера/времени и общий кэш. Контакт ещё не получен, поэтому реальная проверка SEC остаётся незавершённой частью GS-016.
