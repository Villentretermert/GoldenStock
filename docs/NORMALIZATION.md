# GS-011 — факты и противоречия

Обновление 2026-10-24: реализована политика gs011-v2-source-rounding. Аналитик явно выбирает округление до последнего показанного разряда; сравниваются интервалы ±половина этого разряда с учётом масштаба/процентов. Старые факты без такого подтверждения остаются точными. Контекст сравнивается прежде значений. Смена политики делает прежние снимки устаревшими. Исторический текст ниже описывает v1.

Реализовано 2026-10-23. Нормализация детерминированная; выбор метрики и контекста делает аналитик. Автоматическое семантическое сопоставление ИИ ещё не реализовано. Все факты остаются `unreviewed`; утверждение — GS-012.

## Сценарий

Files & jobs → View extracted evidence → **Normalize** у строки → выбрать точное число и заполнить контекст → **Save unreviewed fact** → **Facts & conflicts**. Из карточки компании тоже есть переход к фактам. При длинном тексте нужно ввести число, встречающееся в этой строке ровно один раз; неоднозначный выбор отклоняется. Пустота не превращается в ноль.

**Create corrected version** создаёт новую версию; **Show version history** показывает прежние. Исправление может сослаться через API на другой доступный оригинал, указав `supersedes`. У одной версии только один прямой преемник. Предыдущий факт сохраняется. Restated не означает автоматический выбор нового значения.

Девять основных метрик согласованы; MAU/LTV поддержаны как дополнительные из исходного запроса. Отсутствующий LTV показывается в missing_metrics, не выводится из ARPU или Retention.

## Нормализация

Десятичная арифметика Decimal, максимум 28 цифр входа. Английский формат: `1,234.50`, `-120`, Unicode minus, отрицательное число в скобках. Десятичная запятая, экспонента, NaN, сноски в числе и N/A отклоняются. Полный знак/процент должны попасть в выбранный фрагмент.

- money/count: units ×1, thousands ×1000, millions ×1000000, billions ×1000000000.
- fraction ×1; percent ÷100; bps ÷10000. У коэффициента нет валюты или масштаба millions.
- Денежная валюта выбирается явно из USD/RUB/GBP/EUR/BRL/HKD/CNY/JPY/CHF/MXN/COP. FX-конверсии нет.
- MAU — неотрицательное целое; коэффициент вне 0–1 сохраняется с предупреждением, поскольку отрицательный ROE может быть реальным.

Период имеет тип instant/quarter/ytd/year/custom и даты. Для instant нет start; quarter ограничен 80–100 днями, year 350–380, YTD не длиннее 380. Это проверки формы, не знание финансового календаря эмитента; нестандартный период задаётся custom. FY не выводится из имени файла. Различие текущего промежуточного периода и накопленного YTD согласуется с [IAS 34](https://www.ifrs.org/content/dam/ifrs/publications/pdf-standards/english/2022/issued/part-a/ias-34-interim-financial-reporting.pdf?bypass=on).

## Сравнение и предупреждения

Политика `gs011-v1-exact`: абсолютный и относительный допуски равны нулю. Это консервативное рабочее правило, а не подтверждённый пользователем допуск округления. Уточнить на контрольной точке после GS-012.

Сравниваются активные личные факты одной компании и метрики. Совпасть должны тип/даты периода, периметр с детализацией, стандарт, определение метрики, валюта и каноническая единица. Текстовые определения сравниваются без учёта регистра, без семантического понимания синонимов. Разный масштаб уже учтён в числе.

Сопоставимые разные profit/equity дают **blocker**; остальные числовые расхождения — warning. При одинаковой дате окончания, но разном контексте — context_mismatch, без объявления числового противоречия. Разные даты окончания считаются нормальной временной серией. Неизвестные scope/accounting дают context_incomplete и не участвуют в уверенном сравнении.

OCR, непроверенный кэш формулы, скрытый лист и restatement сохраняют предупреждения. Старые значения не перезаписываются и новые публикации не выбираются автоматически. Метки blocker пока информационные: утверждение модели здесь отсутствует; GS-012 должен использовать их в своём шлюзе проверки.

## Хранение и API

Миграция 0007: таблица facts — org/owner/company, версия оригинала, fingerprint, supersedes, JSON контекста/числа/происхождения, дата. Сохраняются SHA-256 оригинала, версия парсера, индекс элемента, точный диапазон символов и координаты источника. Политика нормализации зафиксирована в каждом факте. Обновления/удаления через API отсутствуют; добавление журналируется.

`POST /api/v1/facts`, `GET /api/v1/facts?company_id=...&history=true`, `GET /api/v1/facts/{id}`, `GET /api/v1/metrics`, `GET /api/v1/conflicts?company_id=...`. CSRF обязателен для записи. Факты приватны даже для администратора аккаунтов; клиент не может подставить произвольное готовое value — число извлекается сервером из доступного оригинала.

Fingerprint и уникальное ограничение исключают повторную запись одного запроса. Ссылки supersedes имеют уникальное ограничение; два одновременных разных исправления не создают ветвление. Пилотный предел — 500 версий фактов на аналитика/компанию. Очередь конфликтов вычисляется по текущим активным фактам; API возвращает первые 200 пар, UI первые 30. Полные total и blocker_count учитывают все пары; усечения обозначены. Хранимое разрешение конфликта и решения аналитика — GS-012.

Остальные проверки очереди и восстановления после аварии проходят. Браузер проверяет реальный сценарий; итог в CHANGELOG. Синтетические тесты не измеряют качество ИИ и не заменяют ручной эталон GS-004.
