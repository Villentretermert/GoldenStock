# Фрагменты исходного текста для ИИ

GS-028 позволяет передать локальному ИИ длинную страницу PDF по частям. Это выбор входа для предложений метрик в AI workspace. Одна задача содержит до восьми элементов или часть длинного элемента, общий JSON evidence ограничен 6000 символами с учётом экранирования.

## Работа в кабинете

1. В Files & jobs загрузить оригинал и выполнить Extract English document.
2. В извлечении найти нужную PDF-страницу или ячейку и нажать **Preview AI evidence**. Альтернативный путь — AI workspace, выбор оригинала и **Preview evidence**.
3. Проверить текст под **Source fragment**, страницу и диапазон символов. Заголовок, масштаб и годовая колонка могут находиться в соседней части. Ссылка **Open full source item** открывает полный элемент для сверки.
4. Выбрать профиль и нажать **Suggest metrics from this fragment**. Откроется сохранённая задача с точным исходным текстом. Обновить страницу для результата.
5. **Preview next fragment** продолжает чтение с первой ещё не переданной позиции. Просмотр не запускает ИИ. Следующий запрос отправляет аналитик отдельно.
6. В предложении открыть **Check context and create a fact**, сверить число с оригиналом и заполнить контекст. Запись остаётся unreviewed до решения на Review.

Фрагменты без финансовых чисел могут завершиться `no_numeric_evidence` или пустым списком предложений. Ссылка продолжения доступна и у неудачной задачи. Граница фрагмента не утверждает полноту финансовой строки. Если одно слово без пробелов само превышает лимит, система предлагает ручную проверку вместо обрезки слова.

## Контракт и происхождение

`ai_evidence.source_window` выбирает текст на сервере из завершённого `Extraction`. Для каждой записи сохраняются `item_index`, `source_range` в символах Python с правой границей вне диапазона, `source_length`, исходный локатор и SHA-256 оригинала. Текст дословно совпадает с этим диапазоном. Evidence ID сохраняет формат `version_id:item_index`, поэтому ссылка нормализации ведёт к прежнему полному элементу.

Разделение предпочитает конец строки во второй половине доступного окна, затем пробел. Непробельные токены не разрезаются. JSON-лимит считается по фактической сериализации, включая Unicode и escape-последовательности. Пустые элементы пропускаются. Веб-страница показывает позиции начиная с единицы, API использует позиции начиная с нуля.

`GET /api/v1/ai/proposal-evidence` возвращает предпросмотр и `next_cursor`. `POST /api/v1/ai/proposals` принимает только `job_id`, `offset`, `text_offset` и профиль. Переданный клиентом текст отклоняется. Проверки сессии и владельца выполняются на обоих путях, POST также требует CSRF. Работодатель и администратор не получают доступ к личным оригиналам аналитика.

В `AIRun.input` фиксируются текст, курсор продолжения и `gs028-source-window-v1`. Повтор того же запроса возвращает прежнюю задачу. Другой диапазон создаёт другую задачу. Retry использует сохранённый вход. Старые задачи читаются без пересоздания. Миграция БД не требуется.

Используется существующий Wrapper `OllamaProvider`. Он ограничивает профили, проверяет digest, схему ответа, ссылки и цитаты. Фрагменты не добавляются в RAG автоматически. RAG по-прежнему получает подтверждённые личные факты. CrewAI, LangGraph и MCP для этого последовательного выбора текста не требуются. Пользователь управляет выбором через Preview и Next, а смена модели выполняется через Local AI profile.

AI Lab сохраняет прежний отдельный контракт эталонного набора. Автоматического переноса фрагментов в эталоны или разделения корпуса внутри Lab здесь нет. Резерв GS-004 хранится отдельно. Качество контекста и реальная accuracy ожидают ручной разметки.

## Проверки

На 24 рабочих извлечениях корпуса обнаружены 215 элементов сверх прежнего лимита. Они разложены на 430 окон без вызова ИИ. Для каждого длинного элемента конкатенация выбранных частей побайтово в UTF-8 совпадает с исходным текстом. Все evidence укладываются в 6000 символов JSON. Резерв не открывался.

Тесты API проверяют права двух чужих аккаунтов, CSRF, запрет произвольного evidence, очередь, повторы, сохранённый вход и старые задачи. Отдельные проверки покрывают Unicode, длинные токены, пустые элементы, позиции и непрерывность диапазонов. Результаты браузера и регрессионного прогона фиксируются в карточке GS-028 и CHANGELOG.
