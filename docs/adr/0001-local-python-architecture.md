# ADR-0001: локальное Python-приложение
Дата: 2026-10-21. Статус: проектное решение для реализации GS-005, версии библиотек ещё не закреплены.

## Решение
Модульный монолит на Python с FastAPI и UI на NiceGUI. UI-сервис вызывает прикладные сервисы/API с контекстом пользователя, не подключает браузер к ИИ. PostgreSQL хранит доменные данные. Файлы за интерфейсом FileStore сначала находятся в локальном Docker volume; дальнейший S3 adapter не меняет доменную логику. Не добавляем отдельный объектный сервер для первого локального запуска.

Фоновые задачи отделены от API. Для первого варианта — PostgreSQL job table с lease, heartbeat и атомарным захватом, без отдельного брокера. Outbox создаётся в транзакции с доменным событием. Повтор обрабатывается по ключу (tenant, task type, input hash, config hash). После исчерпания попыток — failed и явный ручной retry. Конкретный механизм SELECT FOR UPDATE SKIP LOCKED проверяется интеграционными тестами GS-008.

Inference — отдельный внутренний сервис. Адаптер поддерживает локальные HTTP endpoints, без внешних провайдеров по умолчанию. GPU concurrency=1, каждый OCR/LLM task получает лимит ресурсов и времени. Позднее AI Lab запускает несколько экспериментов в очереди на одном GPU; реальная одновременная inference разрешается только после benchmark.

## Почему
Python-first соответствует запросу. UI в Python уменьшает число языков основного приложения. Прототип GS-003 проверяет сценарии и композицию, но не является доказательством работоспособности NiceGUI; UI-framework smoke test обязателен в GS-005. Один компьютер не требует распределённых микросервисов, брокера и облачных служб. Отдельные workers сохраняют отзывчивость интерфейса.

## Альтернативы и ограничения
React даёт более широкий UI-контроль, но увеличивает долю TypeScript. Streamlit удобен для демо, но рабочие сценарии проверки и прав требуют тщательной организации сессий. FastAPI + серверные шаблоны проще, но сложнее интерактивное сравнение источников. NiceGUI принят как кандидат реализации с правом пересмотра после smoke test.
PostgreSQL-очередь потребует собственной логики retries/lease; не обещаем exactly-once. Защищаем побочные эффекты транзакцией и идемпотентностью. Локальный диск не обеспечивает отказоустойчивость и требует резервной копии на другом носителе.

## Проверки перед реализацией
15 сессий, индивидуальное состояние UI, восстановление worker, идемпотентный экспорт, отсутствие опубликованного inference порта, offline UI assets. Зависимости pin/lock после проверки поддерживаемого Python.
