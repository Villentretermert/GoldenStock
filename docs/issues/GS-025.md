# GS-025: Полные годовые отчёты больше 250 страниц

Статус: TODO. Приоритет: P0 для приёмки полных годовых отчётов. Дополнительная задача по результатам реального UAT, после исходного плана GS-001–024.
Зависимости: GS-008, GS-010, GS-011, GS-024. Ответственный — разработчик, проверяющий реального результата — пользователь.
GitHub issue: https://github.com/Villentretermert/GoldenStock/issues/25.

## Проблема

Пользователь загружает английский PDF до 50 MiB, но действующий парсер ограничен 250 страницами. Официальный Annual Report 2025 JPMorgan содержит 364 страницы и попадает под этот лимит. Отдельный раздел банка на 167 страницах успешно обработан, но не заменяет поддержку полного оригинала. Источник: https://www.jpmorganchase.com/ir/annual-report.

## Результат

Полный длинный PDF обрабатывается в ограниченных порциях с сохранением SHA-256 исходного оригинала, исходной нумерации страниц и стабильного происхождения. Неполный результат явно отмечен и не считается завершённым извлечением. На первом этапе требуется полный JPMorgan 2025, затем проверка HSBC при наличии исходного файла.

## Порядок

1. Зафиксировать воспроизводимый отказ полного отчёта и измерения памяти/времени.
2. Спроектировать порционную обработку с лимитами памяти, CPU, общего числа элементов и размера результата, без простого снятия защит.
3. Сохранить lease, отмену, возобновление/идемпотентность, исходные локаторы и маркировку частичного результата.
4. Проверить PDF с текстом и сканами, отказ середины, повреждённый файл и чужой доступ.
5. Повторить реальный JPMorgan и зафиксировать состав общего времени для цели 10 минут.

## Приёмка

Нет потерь или повторов страниц при возобновлении. Факты и UI ссылаются на оригинальную страницу, частичный прогон не выдаётся за полный. Ресурсы остаются ограниченными. Реальная ручная разметка и 95% проверяются отдельно в GS-004, этот технический тест их не подтверждает.
