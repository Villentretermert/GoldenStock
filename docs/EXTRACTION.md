# GS-010 — локальное извлечение документов

Реализовано 2026-10-23. Это технический контур сырых данных. Качество на реальных отчётах эмитентов ещё не измерено: ручная разметка GS-004 не готова. Цель 95% не объявляется достигнутой.

## Как пользоваться

1. В Files & jobs загрузить английский PDF, PPTX или XLSX до 50 MB.
2. Дождаться `succeeded` проверки оригинала и обновить страницу.
3. Нажать **Extract English document**. Обработка идёт в локальной очереди.
4. После завершения обновить страницу и открыть **View extracted evidence**.
5. Сопоставить сырые значения с оригиналом по ссылке. Все элементы `unreviewed`; утверждение появится в GS-012.

Повторный клик не создаёт вторую обработку. Ошибку можно повторить через Retry processing. Результаты привязаны к неизменяемой версии оригинала и SHA-256. Автор видит результат, коллеги и другой фонд — нет. Новый документ или версия не заменяют ранее сохранённый результат.

## Форматы и границы

| Формат | Результат | Ограничения |
|---|---|---|
| PDF с текстом | Текст страницы и обнаруженные таблицы; строка/столбец и координаты таблицы/ячейки | Нет гарантии обнаружения таблиц без линий, сложных объединений и диаграмм |
| Скан PDF | Tesseract `eng`: слова, координаты, блок/абзац/строка, confidence | Семантическая таблица скана не восстановлена; поворот, шум и сложная вёрстка требуют проверки |
| Смешанный PDF | Нативный текст плюс OCR страниц с изображениями | Дубли помечены `native_and_ocr_overlap`; не суммировать автоматически |
| XLSX | Ячейки занятого прямоугольника, пустоты, объединения, формулы и сохранённые значения, формат числа | Формулы не выполняются. Кэш непроверенный, может отсутствовать; ноль не подставляется. Скрытые листы помечены |
| PPTX | Текст фигур/групп и ячейки таблиц с объединениями | Изображения/диаграммы не распознаются; показано предупреждение |

Английский — поддерживаемый вход и режим OCR. Автоматического определения языка нет: `language_status=analyst_confirmation_required`. Другие языки не переводятся и не считаются поддержанными. Отрицательные числа и сноски сохраняются без финансовой интерпретации. OCR confidence — оценка распознавания слова, не вероятность корректности финансового факта; для нативных данных confidence=null.

## Компоненты и API

`extraction.py` — адаптеры и единый результат. `parser_process.py` — дочерний процесс без GS-секретов в окружении, ограниченный вывод, тайм-аут и завершение группы процессов Linux. `jobs.py` продлевает lease и heartbeat, перепроверяет доступ и не даёт старому worker записать результат. Миграция `0006` добавляет фазу задания и таблицу `extractions` с JSON сырых элементов. Нормализованные метрики — GS-011.

- `POST /api/v1/jobs/{id}/extract`: после проверки оригинала ставит извлечение в очередь; права автора и CSRF обязательны.
- `GET /api/v1/jobs/{id}/extraction?offset=0&limit=100`: авторизованный просмотр, максимум 200 элементов на ответ.
- `/extraction/{id}`: экранированный HTML, оригинал, происхождение, предупреждения и пагинация.

Лимиты: 250 страниц/слайдов, 50 000 элементов, 8 MiB JSON, 25 млн пикселей OCR-страницы. Linux-процесс: 3 GiB адресного пространства, 180 секунд CPU, 300 секунд общего времени; OCR страницы до 30 секунд. Превышение приводит к ошибке без сохранения частичного результата. Это защитные границы, не обещание скорости. Оригинал сохраняется.

Production OCR работает в Docker Linux; Windows .venv проверяет нативные форматы без установки системного Tesseract. Дочерний процесс не является полноценной песочницей против неизвестных уязвимостей библиотек. Worker остаётся во внутренней сети; внешние AI API и сетевой загрузчик не подключены.

## Зависимости и дальнейшее развитие

[pdfplumber](https://pypi.org/project/pdfplumber/) читает текст/таблицы, [pypdfium2](https://pypi.org/project/pypdfium2/) растеризует страницы, [pytesseract](https://pypi.org/project/pytesseract/) оборачивает локальное OCR с тайм-аутом; openpyxl читает Excel, python-pptx — презентации. Версии Python закреплены в requirements.lock. Tesseract устанавливается из Debian в образ; системные версии проверять при пересборке.

Wrapper здесь — единый контракт поверх разных библиотек: можно менять парсер, сохраняя происхождение и статус проверки. LLM/RAG не нужны для нативного чтения форматов; реестр ИИ и RAG остаются GS-013–015.

## Проверки

- Полный pytest: 52 passed, 1 skipped; затем 2 passed для отзыва доступа/смены lease во время обработки. Всего проверено 54 теста. Windows OCR пропущен и отдельно проверен настоящим Tesseract в Docker.
- Синтетический корпус: текстовый PDF, PDF-таблица, скан, XLSX с отрицательным числом/пустотой/объединением/формулой, PPTX-таблица с объединением, повреждённый PDF, превышение размера листа.
- `scripts/check_extraction.py`: реальное OCR с проверкой Profit, -120, million; Excel/PowerPoint, лимитированный Linux-процесс и принудительный тайм-аут.
- PostgreSQL: миграции, конкурентные повторы, аварийное восстановление очереди и защита от старого worker проходят.
- Браузер: десять сценариев, включая извлечение реальным worker и просмотр; ошибок JS, внешних запросов и мобильного переполнения нет. QA-аккаунт отключён.
- `pip check` проходит. CI дополнен OCR-проверкой, удалённый GitHub Actions не запускался.

Локальные скриншоты: `design/previews/extraction-desktop.png`, `extraction-mobile.png`. Проверки и демодокументы не являются ручным финансовым эталоном и не подтверждают точность на реальных отчётах.
