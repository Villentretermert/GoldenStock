# GS-012 — проверка аналитиком
Дата: 2026-10-23. Локальная реализация; финансовый расчёт ещё не подключён.

## Сценарий
Открыть компанию → Facts & conflicts → Open analyst review. Слева исходный текст и координаты, справа значение, единицы, период, периметр и предупреждения. Оригинал доступен по ссылке. Для каждого решения обязательна причина: Confirm, Reject and exclude или Reopen. Исправление создаёт новую версию через GS-011; подтверждение прежней версии не переносится.

Можно проверять факты выборочно и продолжать позже. Для сохранения **verified_inputs** все включённые факты должны быть подтверждены. Неразрешённое сопоставимое расхождение profit/equity блокирует серверный POST независимо от интерфейса. Отклонённые факты исключаются явно и сохраняются в снимке с причиной. Пустой набор сохранить нельзя. Это рабочая политика до ответов контрольной точки, более строгая, чем выборочная проверка качества ИИ.

## Данные и код
- `FactReview` — добавляемая запись решения, автор, причина, последовательная ревизия. `expected_revision` отклоняет устаревшее решение с HTTP 409.
- `InputSnapshot` — неизменяемые факты, исключения, решения, предупреждения и версии политик. Хеш состояния включает текущие версии фактов и идентификаторы решений. Изменение факта или решения делает снимок stale; история остаётся доступной.
- `reviews.py` — серверное вычисление состояния, проверка прав, решения и снимки; `review_ui.py` — Python-страница. `facts.py` показывает актуальный статус проверки.
- Миграция `0008_reviews.py`. Блокировка строки компании в PostgreSQL сериализует запись фактов, решений и снимков. Повтор сохранения одного состояния возвращает тот же ID; чужие личные данные недоступны даже администратору фонда.

## Проверки
89 pytest passed, 1 skipped (OCR в Windows). OCR отдельно прошёл в Linux-контейнере; также XLSX/PPTX и тайм-аут парсера. PostgreSQL: конкурентные решения дают 201/409, три одинаковых сохранения дают один снимок; прежние проверки очереди и версий проходят. 15 браузерных сценариев, включая блокировку, отклонение ошибочного масштаба, сохранение и stale после повторной проверки. Нет ошибок JS, внешних запросов и мобильного переполнения; QA-доступ отозван.

## Ограничения
Статус снимка не утверждает оценку: расчётных моделей ещё нет. Будущий расчёт обязан проверять `eligible_for_future_calculation`, актуальность входов и полноту требуемых метрик. Сейчас снимок охватывает все активные личные факты данного аналитика по компании, без отбора по шаблону/периоду. Наличие предупреждений не блокирует сохранение после решения аналитика. Политика расхождений `gs011-v1-exact` имеет нулевой допуск. OCR возвращает слова с координатами; PDF-страница внутри кабинета пока не отображается. 95% accuracy не измерены — GS-004 требует ручного эталона.
