# GS-013–016: локальный ИИ, задачи и знания
Дата: 2026-10-24. GS-013/014 реализованы в техническом объёме; GS-015 — первая версия лексического RAG по подтверждённым фактам. GS-016 остаётся IN PROGRESS до реальной проверки публичного SEC-сценария и итогового обзора этапа.

## Как пользоваться
1. Открыть компанию → AI workspace. Загрузить и извлечь английский документ через Files & jobs.
2. Выбрать Extracted original и локальный профиль, нажать Suggest metrics. Одна задача обрабатывает до 8 элементов извлечения в пределах 6000 символов JSON. Для следующих элементов изменить Evidence offset; обработки целого 50 MB файла одним запросом нет.
3. Обновить список задач, открыть результат. Предложение содержит цитату, число и предположенный контекст. По ссылке проверить контекст и создать обычный unreviewed факт; пропуски заполнить по оригиналу.
4. На Review подтвердить все включённые факты. Create summary получает до четырёх найденных подтверждённых фактов. Результат — черновик с цитатами, периодом входов и признаком устаревания, а не оценка компании.
5. Export private knowledge pack скачивает JSON представление личных подтверждённых фактов с происхождением и решениями. Другой аналитик или фонд их не видит. Все модели используют тот же пакет знаний.
6. Research SEC and summarize предназначена для JPMorgan, HSBC и Nu. Пока без настроенного `GS_SEC_CONTACT` возвращает понятную ошибку. Контакт запрошен у владельца; реальная сеть ещё не проверена. Сбер/Т-Технологии остаются пробелами английского покрытия.

## Что установлено
В существующем Ubuntu WSL установлен NVIDIA Container Toolkit 1.20.1-1 из официального репозитория. Windows-драйвер не заменялся. Docker перезапущен; база и файлы сохранены. `scripts/setup_gpu.sh` сохраняет прежний daemon.json, если он существовал. На этой машине прежнего файла не было.

Ollama 0.13.5, две загруженные Q4-модели: Qwen3 4B Instruct 2507 и Qwen3 1.7B. Профили и полные digest закреплены в `inference.py`; незаметная замена tag другим содержимым отклоняется. Веса занимают примерно 4 GB на диске. Загрузка выполняется отдельным сервисом `compose.models.yaml`, имеющим интернет только для публичных весов. Во время provisioning inference должен быть остановлен: одновременная работа двух серверов с volume привела к конфликту незавершённого blob; повтор при остановленном inference прошёл.

Запуск GPU: `wsl -d Ubuntu -- env GS_WEB_PORT=8081 docker compose -f compose.yaml -f compose.gpu.yaml --profile ai up -d --wait`. UI — http://127.0.0.1:8081. Inference не имеет опубликованных портов; его Docker-сеть `internal=true`. Браузер обращается только к FastAPI. Cloud-функции Ollama выключены.

## Измерения и выбор
Финальный прогон v5 дополнительно сохраняет хеш JSON-схемы: `gs013-prompt-v5-synthetic.jsonl` и `gs013-prompt-v5-gpu.json`. Qwen4: 3.177/2.945 секунды; Qwen1.7: 2.324/2.385. Пик 5464 MiB, минимум свободно 6623 MiB, до/после занято 2065 MiB. Это повтор на тех же синтетических примерах, не независимый holdout. Промпт и схема доработаны по ошибкам этого набора.
Подробные синтетические результаты: `evaluation/results/gs013-prompt-v2-synthetic.jsonl`, `gs013-prompt-v4-synthetic.jsonl` и соседние GPU JSON. На v4 Qwen4 ответил на две обычные записи за 3.186/3.224 секунды; Qwen1.7 — 2.688/2.358 секунды. Во всех четырёх обычных случаях код метрики и число совпали, но контекст заполнен частично. Это два примера, не эталон и не 95% accuracy. Третий, заведомо вредоносный, вход блокируется детерминированным правилом; это не успех модели. Неудачные v2-ответы сохранены.

На v4 общий пик GPU 5462 MiB, минимум свободной памяти 6625 MiB, после прогона 2065 MiB занято против 2063 MiB до. Замер включает другие приложения, делается периодически и не гарантирует резерв при их изменяющейся нагрузке. Настройка Ollama задаёт 2 GiB GPU overhead, одну модель и один запрос; короткий контекст и выгрузка после ответа уменьшают конкуренцию. Первый холодный прогон v1 занимал до 43 секунд; дисковый кэш влияет на задержку.

Предварительный профиль по умолчанию — qwen4, qwen_small доступен для сравнения. Оба требуют реального отложенного корпуса GS-004. Облачная аренда и внешние AI API сейчас не используются. Точная денежная смета электричества требует тарифа и замера потребления; 45 документов/день нельзя перевести в стоимость по двухстрочному smoke test. Целевые 5 минут для сводки ещё не являются SLA при очереди 15 сотрудников.

## Изменения кода
- `inference.py`: фиксированные профили, JSON-схемы, лимиты, проверка digest/цитат/чисел; результаты unreviewed.
- `ai_runs.py`, миграция 0009: приватная очередь, идемпотентность, отмена/повтор, lease, аудит, повторная проверка активного аккаунта.
- `knowledge.py`: лексические векторы, поиск по принятым фактам текущего аналитика, экспорт знаний; версия индекса фиксирована.
- `public_sources.py`, миграция 0010: ограниченный SEC-коннектор, неизменяемые публичные ответы и SHA-256, 15-минутный кэш, до 1 запроса/секунду. Данные XBRL остаются unreviewed, теги и периоды не смешиваются в расчёте. Выборка до четырёх поддержанных последних метрик не обещает полное покрытие отчётности.
- `ai_ui.py`: интерфейс задач и источников; `worker.py` поддерживает heartbeat во время inference. Обоснование архитектуры и обучение терминам — ADR-0004.

## Ограничения приёмки
Проверки: 105 pytest прошли, 1 OCR тест пропущен в Windows (Docker OCR проверялся ранее). PostgreSQL с миграциями до 0010 проверил конкурентные записи и единственный AI-вызов. Браузер с реальным Ollama прошёл 18 сценариев; UI desktop/mobile просмотрен, QA-аккаунт отключён. Отдельные проверки последних изменений оригинала JSON и округления также проходят. 95% не подтверждены.
Сбор SEC подготовлен и проверен на фикстурах, но требует реального контактного email и сетевого прогона. GS-016 не завершена. Семантический индекс всех документов, автоматический перенос правок между установками, полная обработка документа по всем фрагментам и числовая оценка качества на реальном holdout ещё отсутствуют. Финансовый расчёт остаётся GS-017–019. После завершения GS-016 обязательны презентация и не менее 10 вопросов.
